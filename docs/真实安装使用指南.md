# 真实安装使用指南

更新：2026-10-20。适用：Ubuntu 20.04，已安装ROS1 Noetic。

## 本版先看

- 日常只改规则内的`enabled: true/false`，不删除阈值。每个模块、时间/频率和质量规则的开关都已写全。
- 当前文件将每个模块的时间戳规则完整展开；stream_defaults只共享计算约定，开关不会藏在公共继承里。
- 日志删除producer_instance_id、module_epoch、metric、effective_config_sha256、data_sha256；CSV也不再有实例/代际列。
- 程序为C++，源码函数、配置、消息和启动参数均补充中文说明。
- 默认新工作区是`~/robot_health_ws_20261019`，不会覆盖旧版本；不要把不同工作区的同名包混着source。
- 配置开关示例见[可选规则与日志变更](可选规则与日志变更.md)，代码流见[代码与数据流](代码与数据流说明.md)，实测证据见[测试报告](测试报告.md)。

## 1. 程序装在哪、做什么

把这个部署目录看成“安装材料”，安装后日常运行的是 `~/robot_health_ws_20261019` 中的程序。

```text
部署目录（桌面或机器人家目录）
├── README.md
├── scripts/                      安装依赖、复制源码并编译
├── fastlio_health_monitor/        GitHub仓库中的独立C++ ROS包
│   或 src/fastlio_health_monitor/  桌面离线交付包中的独立C++ ROS包
├── docs/真实安装使用指南.md       本文；接口、参数和测试说明也在docs/
└── evidence/                     仅桌面离线交付包附带完整原始测试证据

安装后：~/robot_health_ws_20261019/src/fastlio_health_monitor/
```

它接收数据、判断质量、显示结果、记录日志。你的雷达驱动、MAVROS、定位算法照常由原机器人系统运行。本程序不修改输入消息，也不生成新的定位结果或自动控制飞机。

带RViz时能看健康面板和已有点云；没有图形界面时只运行后台节点。标准构建不依赖FAST-LIO或Livox专用消息，默认雷达输入使用PointCloud2。已有Livox驱动且需要CustomMsg时可增加--livox构建选项。

## 5. 先改正确的YAML

**修改安装后工作区里的文件**，不要只改桌面材料副本。

| 用途 | 安装后配置文件 |
| --- | --- |
| 真实机器人，五模块含可选测距 | `~/robot_health_ws_20261019/src/fastlio_health_monitor/config/health_robot.yaml` |
| bag回放，五模块含可选测距 | 同目录 `health_bag.yaml` |
| 三模块回放 | 在health_bag.yaml把imu_attitude和ground_range的模块enabled改为false |
| 托管定位启停的进程配置 | 同目录 `runtime_localization.example.yaml` |

主配置现在只有三份：实机health_robot.yaml、回放health_bag.yaml、托管启停runtime_localization.example.yaml。实机和回放独立调参；旧重复配置与最小/三模块配置已移出主目录。

打开文件的方式随你，可以使用IDE或：

```bash
nano "$HOME/robot_health_ws_20261019/src/fastlio_health_monitor/config/health_robot.yaml"
```

先核对五件事：

1. topic是不是你真实发布的话题；用 `rostopic list`、`rostopic type 话题` 查看。
2. IMU加速度是不是m/s²；MAVROS一般按本配置mps2接入，不能误乘9.80665。
3. 频率是不是配置预期值；用 `rostopic hz 话题` 看实际情况。
4. Odometry的header.frame_id/child_frame_id是否与配置camera_init/body一致；换定位节点时要改。
5. 姿态参考方向、设备量程和机动阈值是否符合你的机器人；30/45度、测距变化率等是工程初值。

参数详情见[YAML配置说明](YAML配置说明.md)。改后重启监控加载；本版本没有运行中热更新。

## 10. 机器人跑监控，电脑看RViz

电脑也安装本包GUI版本，只在电脑启动rviz.launch，不再重复启动监控。两台机器网络必须双向互通。

假设机器人IP为192.168.1.10，电脑IP为192.168.1.20，**要替换为真实地址**：

机器人上启动原系统和监控的每个相关终端：

```bash
export ROS_MASTER_URI=http://192.168.1.10:11311
export ROS_IP=192.168.1.10
unset ROS_HOSTNAME
```

加载ROS/工作区后：

```bash
roslaunch fastlio_health_monitor live.launch rviz:=false
```

电脑上（Bash）：

```bash
source /opt/ros/noetic/setup.bash
source "$HOME/robot_health_ws_20261019/devel/setup.bash"
export ROS_MASTER_URI=http://192.168.1.10:11311
export ROS_IP=192.168.1.20
unset ROS_HOSTNAME
roslaunch fastlio_health_monitor rviz.launch
```

ROS_IP是“本机别人能访问到的地址”；ROS_MASTER_URI指向“master在哪里”。只配置master能看到话题但收不到数据，常见原因是另一个节点公布了不可达的IP/主机名。不要在远程查看时沿用本机示例的127.0.0.1。ROS1数据连接还使用动态端口，只通11311不够。

跨电脑只看健康面板需要较小带宽；点云本身带宽更大。RViz Fixed Frame默认camera_init，如果换成map/odom等，要和真实定位frame、TF一起修改。

## 11. 正常关闭定位、过一会重启怎么接

仅订阅消息时，“正常停机”和“意外断流”外观一样。默认被动接入不会猜测正常停机，停止定位可能按超时报警。

有两种接法，选一个：

### A. 你的机器人管理程序发布真实RuntimeState

接口 `/robot_runtime/module_state`，binding为sensors或localization，非latched，周期心跳，序号递增。停定位前进入STOP/STOPPING，确认停止后STOP/STOPPED；重启用新实例ID，再RUN/STARTING到RUN/RUNNING。控制器失联仍按UNKNOWN/ERROR处理。字段、约束和状态表见[程序接入接口](程序接入接口.md)。

### B. 由包内控制器实际托管定位进程

先编辑两个文件：

```text
~/robot_health_ws_20261019/src/fastlio_health_monitor/scripts/start_localization.sh
~/robot_health_ws_20261019/src/fastlio_health_monitor/config/runtime_localization.example.yaml
```

脚本改成你真实的定位启动命令，最后用exec，例如：

```bash
#!/usr/bin/env bash
set -eo pipefail
source /opt/ros/noetic/setup.bash
source /你的真实机器人工作区/devel/setup.bash
exec roslaunch 你的真实定位包 你的真实定位.launch
```

上面包名/路径是占位符，必须替换；运行配置的supervised_ros_node也要改成实际rosnode名称。默认autostart=false，不会自动运行占位脚本。要自动启动再改true。

只有定位由这个控制器启动时才用托管方式；不要同时从原系统重复启动同一个定位节点。传感器仍由原系统运行。

一键启动托管控制器、监控和界面：

```bash
bash -c '
source /opt/ros/noetic/setup.bash &&
source "$HOME/robot_health_ws_20261019/devel/setup.bash" &&
export ROS_MASTER_URI=http://127.0.0.1:11311 &&
exec roslaunch fastlio_health_monitor live_managed.launch
'
```

无界面加rviz:=false。再开一个相同ROS环境的Bash终端：

```bash
source /opt/ros/noetic/setup.bash
source "$HOME/robot_health_ws_20261019/devel/setup.bash"
export ROS_MASTER_URI=http://127.0.0.1:11311
# 初次启动/重启
rosservice call /robot_runtime/control "{binding: 'localization', command: 'RUN'}"
# 正常关闭，等待STOPPED确认
rosservice call /robot_runtime/control "{binding: 'localization', command: 'STOP'}"
# 过一段时间后再启动
rosservice call /robot_runtime/control "{binding: 'localization', command: 'RUN'}"
```

控制器真实启动/停止其拥有的子进程，检查ROS节点存活，并记录过程；不是只发一个STOPPED文字来掩盖错误。占位配置未填写时不能声称正常重启已经接好。

## 12. 无界面查看诊断和日志

### 12.1 终端看实时诊断

不启动RViz也会发布同样的诊断。另开一个Bash终端即可；只看以下标准消息话题，加载ROS环境就够，不要求安装GUI或本包的RViz插件。

```bash
source /opt/ros/noetic/setup.bash
export ROS_MASTER_URI=http://127.0.0.1:11311
```

上面用于实机本地11311。当前本机bag回放使用33522时，改为：

```bash
export ROS_MASTER_URI=http://127.0.0.1:33522
```

远程查看换成机器人真实IP，并按第10节配置查看端ROS_IP，不能把127.0.0.1当远程地址。

**最直观：按1秒间隔刷新总体健康文字。**

```bash
watch -n 1 "rostopic echo -n 1 '/fastlio_health_monitor/diagnostics/status[0]/message'"
```

当前程序固定将overall放在diagnostics的status[0]。输出会包含OK/WARNING/ERROR、operational_valid；缺测距时还可标明optional_no_data=1。Ctrl+C只结束这个查看命令，不关闭监控。

只看一次总体完整诊断：

```bash
rostopic echo -n 1 '/fastlio_health_monitor/diagnostics/status[0]'
```

看一次所有模块的详细诊断：

```bash
rostopic echo -n 1 /fastlio_health_monitor/diagnostics
```

看简单数字总状态：

```bash
rostopic echo -n 1 /fastlio_health_monitor/status
```

0=OK、1=WARNING、2=ERROR。数字不区分PAUSED/STOPPED/NO_DATA，详细含义看diagnostics。诊断默认100Hz，不建议直接不带-n连续打印整条数组，容易刷屏。

| 字段 | 查看什么 |
| --- | --- |
| name / module_id | overall、lidar、imu、imu_attitude、localization、ground_range；日志项名为Robot health/logging |
| level / message | 告警级别与具体原因 |
| operating_state | RUNNING、PAUSED、STOPPED、NO_DATA等状态 |
| operational_valid | 当前模块数据/状态是否可用于业务 |
| age_sec / rate_hz | 距最后消息多久、当前源频率 |
| roll_deg / pitch_deg | 横滚角与俯仰角，度 |
| range_raw_m / range_status | 原始测距与是否可用/无数据 |
| logs_normal / log_recording_state | 日志是否正常；RECORDING/FINISHED等 |

模块列表位置会随配置变化，不建议用固定status[1]/[2]来认定IMU或雷达；读取全部后按module_id/name辨认。

如果一直没有输出，先检查是否连接同一个master，以及监控是否仍在运行：

```bash
rostopic list
rosnode list
rostopic info /fastlio_health_monitor/diagnostics
```

如果自定义YAML改过diagnostics_topic/status_topic，上述命令也相应改成实际话题。

### 12.2 查保存的日志

默认当前用户目录：

```text
~/.ros/robot_health/health/<run_id>/events.0.jsonl
~/.ros/robot_health/health/<run_id>/metrics.0.csv
~/.ros/robot_health/playback/<run_id>/events.0.jsonl
~/.ros/robot_health/runtime/<run_id>/events.0.jsonl  # 托管启停时
```

启动终端会打印本次log目录。每次启动新建run，目录内还有config_source.yaml、effective_config.yaml、manifest.json和编译源码哈希。

```bash
ls -td "$HOME/.ros/robot_health/health/"*/ | head -1
```

打开打印出来的目录看events和metrics即可。日志不是原始数据录包；要保存原始输入另用rosbag record。

| 时间 | 含义 |
| --- | --- |
| bag_elapsed_sec | /clock减bag起点，回放到第几秒；实机无bag为空 |
| source_stamp_sec | 被检测消息的header.stamp；没有关联消息为空 |
| steady_elapsed_sec | 当前进程记录器创建以来单调秒数，包含等待/暂停 |

STATE_CHANGED是状态变化；CONTROL_INTENT是控制要求；RULE_TRIGGERED才是规则触发；INPUT_AVAILABLE仅说明可选输入收到首帧，不表示质量通过。NO_DATA不伪造高度0。日志记录已结束与日志写入失败是两件事。

## 13. 常见问题

| 现象 | 先做什么 |
| --- | --- |
| 找不到包/加载旧版本 | `rospack find fastlio_health_monitor`，应指向本次~/robot_health_ws_20261019中的包；重新source正确工作区 |
| 改参数不生效 | 改安装后工作区中本次入口实际使用的YAML，重启；桌面材料和工作区是两份 |
| 无界面机器人打不开RViz | rviz:=false；在电脑上编译GUI版本并远程启动rviz.launch |
| 提示没有HealthPanel插件 | 确认GUI编译时BUILD_HEALTH_RVIZ_PANEL=ON并source该工作区；无界面构建不含此库 |
| 旧bag启动后一直ERROR | 首先检查输入是否存在；本机旧包雷达约44秒、定位约64秒才出现，10秒启动期限会先报缺数 |
| 五模块缺测距 | 正常显示灰色无数据，不影响其余四路；收到首帧后就会正常检测，之后断流不会被隐藏 |
| /imu/data_raw显示无姿态 | 可能确实未提供；本配置用融合/imu/data检查roll/pitch，不能把全0四元数当水平 |
| 停定位后超时 | 被动接入不知道停机意图，需要第11节的可信控制状态或托管方式 |
| bag暂停/结束仍报错 | 用replay入口而不是裸rosbag play；EOF确认前仍可能短暂超时，确认后才STOPPED/封存 |
| RViz有面板但没有点云 | 检查/cloud_registered、Fixed Frame、TF；只有健康输入不等于有建图点云输出 |
| 远程有话题列表但无数据 | 检查两端ROS_IP/ROS_HOSTNAME与双向端口连通，master地址正确不代表数据通道正确 |
| apt更新失败 | 先修复目标机器现有的Ubuntu/ROS源、网络或签名；脚本不关闭签名校验、不自动重写软件源 |

Noetic已在2025-05-31结束官方常规维护；本包按你现有系统部署。遇到旧源/签名问题可参考[ROS官方说明](https://discourse.ros.org/t/ros-signing-key-migration-guide/43937)和[Noetic维护状态](https://discourse.ros.org/t/ros-noetic-end-of-life-may-31-2025/43160)。

## 15. Livox接入与重新执行验收

标准PointCloud2模式不需要Livox驱动。只有配置选择`LivoxCustomAdapter`时，先准备可被CMake找到的`livox_ros_driver`，再安装到新工作区：

```bash
bash scripts/install_workspace.sh --gui --livox --workspace "$HOME/robot_health_livox_ws_20261019"
```

如果驱动在其他工作区，应先source那个工作区的setup.bash，并确认`rospack find livox_ros_driver`成功。加速度输入为g时必须在对应IMU的quality写`acceleration_unit: g`，不能使用默认SI值。

重新执行本版验收见[测试报告](测试报告.md)。测试脚本会新建独立错误bag；不会修改原始bag。使用新证据目录，避免覆盖历史证据。

## 2026-10-21 更新：事件筛选与点云显示

健康配置中的logging.events现可按event_type、rule_id、module_id筛选事件JSONL；空列表表示全部记录；当前实机配置全部记录，回放白名单为[RULE_TRIGGERED]。仅修改列表时重启节点即可，升级本次C++代码需要重新编译。语法、计数和作用范围见[日志过滤指南](日志事件过滤配置.md)。

回放布局新增Displays侧栏和最近5秒已配准点云缓存。部分bag的/cloud_registered在录制开始一段时间后才出现，应先核对该话题的首条记录。原始点云与已配准点云需要各自正确的frame/TF；有限时长的显示缓存不代表完整建图结果。
