# 可选规则与日志变更

版本：2026-10-19，包版本0.4.0，健康核心仍为V2。

## 1. 当前主要用法（已按后续要求调整）

主要使用 `enabled: true/false`；保留检测规则和阈值，关闭只改false，恢复只改true。每个模块和支持开关的检测规则都已明确写出enabled。Topic、单位、参考系和发布频率是运行参数；原生布尔设置本身用true/false。

主目录只保留health_robot.yaml、health_bag.yaml、runtime_localization.example.yaml。最小配置/三模块等同源副本已精简；三模块模式直接关闭imu_attitude与ground_range。

```yaml
receive_age_sec:
  enabled: true
  warning_above: 0.1
  error_above: 0.2
acceleration_norm_mps2:
  enabled: false
  warning_above: 100.0
  error_above: 200.0
duplicate_level:
  enabled: true
  level: WARNING
```

[显式开关完整操作说明](配置精简与enabled开关.md)。解析器保留上一版省略/null兼容能力；主要操作已改为显式开关。

## 2. 哪些仍需要写，哪些仍然检查

- 启用模块的id、checker、adapter、topic是接入身份；缺少它们不能订阅正确消息。
- 规划任务还需明确task_state_topic；依赖必须存在且无环；至少一个模块启用。
- 单位、连续性模式和差分时间窗属于计算约定/运行参数，省略使用写明的默认值。例如标准IMU默认mps2，不会根据Topic名猜成g。
- 结构不合法、越界缓冲区、非有限量、零四元数等不能作为可用数据。关闭某项业务阈值不会绕开基础解析守卫。
- disabled的规则意味着“没有检查”，不能理解为“通过了完整质量检测”。关闭接收年龄后也就不再保证及时发现断流。
- YAML改变后要重启，不支持热更新。

## 3. 日志现在是什么样

新JSONL和manifest不再写`producer_instance_id`、`module_epoch`、`metric`、`effective_config_sha256`、`data_sha256`。嵌套context和CSV指标值也过滤同名字段。CSV同时移除旧`epoch`列，指标JSON列改名为`values_json`。

保留rule_id、value、threshold、unit、reason、等级变化、run ID、源配置/有效配置快照、程序和源码版本信息。运行数据仍可按事件序号、规则、三种时间追溯。新版不再为日志启动读完整bag计算哈希。

```text
bag_elapsed_sec,source_stamp_sec,steady_elapsed_sec,module_id,operating_state,health_level,operational_valid,values_json
```

三个记录时间含义保持：bag_elapsed_sec为/clock相对bag起点；source_stamp_sec为关联消息头；steady_elapsed_sec为本记录器启动后的单调秒数。实机没有bag时第一项为空/null；没有关联样本时源时间为空/null。

旧日志不改写。旧分析脚本若读取metric或metrics_json，需要改用rule_id或values_json；本包测试已更新。

## 4. 正常停止与重启没有被日志精简破坏

实例和代际仍在控制协议内部使用，用于拒绝旧心跳、重置旧样本基线；只是从日志输出删除。计划PAUSED/STOPPED暂停数据需求告警，恢复后重新准备；无意图的断流仍按已选择的时间探针判断。验证真实EOF后封存日志，诊断继续发布。

## 5. 布尔子检查同样可选

协方差require_symmetric、require_psd以及IMU required_measurements中的子项，省略时为false；需要检查请显式写true。姿态require_available省略false，姿态缺失仍显示不可用，不能伪造角度。现有完整配置已经显式选择这些项，其原有判断不受影响。
