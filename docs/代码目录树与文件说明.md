# 代码目录树与文件说明

本文对应 GitHub 当前版本。重点逐项说明 fastlio_health_monitor ROS 包中的源码、配置、接口和启动资源，并概述仓库中 FAST-LIO 与 Livox 驱动的位置。健康检测运行功能由 C++ 实现；Python/Bash 仅用于清单生成、占位启动和测试编排。

## 1. 仓库目录概览

~~~text
Robot-Data-Health-Monitoring-Module/
├── FAST_LIO/                         # FAST-LIO 算法、ROS节点、配置和工程文档
├── livox_ros_driver/                 # Livox ROS驱动及通信协议实现
├── fastlio_health_monitor/            # 本文逐文件说明的健康检测ROS包（40个文件）
│   ├── CMakeLists.txt
│   ├── package.xml
│   ├── config/
│   ├── include/fastlio_health_monitor/
│   ├── launch/
│   ├── msg/
│   ├── rviz/
│   ├── scripts/
│   ├── src/
│   ├── srv/
│   └── test/
├── docs/
│   └── 代码目录树与文件说明.md
└── README.md
~~~

FAST_LIO 和 livox_ros_driver 是仓库中保留的独立上游工程。健康检测包可以单独接入 ROS Topic，不要求调用 FAST-LIO 内部类。

## 3. C++源文件

| 文件 | 作用 |
| --- | --- |
| src/health_core.cpp | 检测核心。ConfigLoader读取、检查和解析 YAML；流跟踪器维护样本时间戳与频率窗口；各 Checker 检查雷达、IMU、姿态、测距、协方差、定位运动学或扩展数据；RuleLatch 管理单条规则告警与恢复；LifecycleTracker 识别正常暂停/停止/重启；ModuleMonitor 汇总为模块报告。 |
| src/input_adapters.cpp | ROS输入边界。订阅配置中的消息 Topic，将 ROS 消息字段解析、单位归一并转成核心使用的 Sample；适配器工厂据配置选择消息适配类型。增加一种 ROS 消息类型时，通常从这里扩展。 |
| src/robot_health_monitor_node.cpp | 健康监控主节点。加载 YAML，创建适配器和核心监控对象，按配置频率评估，汇总必需模块状态，发布诊断与简化状态，并向日志器提交事件和指标。 |
| src/bag_playback_node.cpp | 受管 rosbag 播放节点。等待健康监控消费者就绪后启动 rosbag；报告运行/暂停/停止状态，处理播放控制，并在正常 EOF 时发出结束事件以便封存日志。 |
| src/runtime_controller_node.cpp | 运行时进程管理节点。按 runtime YAML 中的 binding 管理配置的外部进程，提供控制服务，监测节点存活与控制心跳，发布 RuntimeState。 |
| src/event_recorder.cpp | 日志实现。将事件和周期指标写入 JSONL/CSV；负责异步队列、线程、文件轮转、刷新、落盘错误和最终封存。 |
| src/health_panel.cpp | RViz/Qt 健康面板。订阅 DiagnosticArray 并显示总体等级、模块状态和详情；它负责呈现诊断结果，不重复执行传感器检测。 |

## 4. 头文件和接口职责

| 文件 | 作用 |
| --- | --- |
| include/fastlio_health_monitor/health_core.h | 定义统一样本、检查发现、配置、模块报告及核心类接口；规定数据从接收、判定到汇总的内部结构。 |
| include/fastlio_health_monitor/input_adapters.h | 定义 ROS 输入适配器接口和适配器工厂；将具体 ROS 消息类型与通用检测核心隔离。 |
| include/fastlio_health_monitor/event_recorder.h | 声明事件记录器、时间轴及日志提交/封存接口。 |
| include/fastlio_health_monitor/bag_log_timeline.h | 从 rosbag 与 ROS 仿真时钟取得回放时间信息，供日志时间字段使用。 |
| include/fastlio_health_monitor/health_panel.h | 声明 RViz 面板、Qt 控件、ROS 订阅回调和界面状态缓存。 |

头文件（.h）通常放类型声明、类成员和函数接口；对应实现放在 .cpp。较短且需内联的时间轴辅助函数直接定义在 bag_log_timeline.h。

## 5. 配置文件

| 文件 | 作用 |
| --- | --- |
| config/health_robot.yaml | 实机监控配置：输入 Topic、适配器和检查器类型、模块启用状态、频率/时间戳/数据质量规则、诊断发布与日志参数。 |
| config/health_bag.yaml | bag 回放使用的独立配置；便于与实机规则分开设置，并允许回放播放器按必需输入等待订阅者就绪。 |
| config/runtime_localization.example.yaml | 托管定位进程的示例设置；需要部署者填入真实工作空间、启动命令、进程 binding 和 ROS 节点名。 |
| test/fixtures/health_extensions.yaml | 测试配置，演示用 Relay/Planning 适配规则接入感知或规划类数据。 |

每个规则的 enabled 字段用于打开或关闭该项判断。具体阈值、单位、默认行为和字段校验以 YAML 内联中文注释及 ConfigLoader 实现为准。

## 6. ROS消息与服务

| 文件 | 作用 |
| --- | --- |
| msg/RuntimeState.msg | 运行控制器与监控节点之间的状态/心跳消息。用于说明某个模块预期处于运行、暂停或停止状态，帮助将有意停止与意外断流区分。 |
| msg/TaskState.msg | 规划任务的目标与活动状态消息；PlanningChecker 可用它判断当前是否预期存在规划输出。 |
| srv/ControlModule.srv | 运行控制服务，按 binding 请求 RUN、STOP、RESET 等操作并返回是否接受及原因；接受请求不代表外部节点已经成功启动。 |

## 7. Launch入口

| 文件 | 作用 |
| --- | --- |
| launch/live.launch | 实机实时监控入口；加载 health_robot.yaml，可选启动 RViz，不会启动硬件或定位算法。 |
| launch/live_managed.launch | 实机监控加运行时控制器入口；启动前需配置外部定位命令和节点名称。 |
| launch/monitor.launch | 只启动 C++ 健康检测节点，可由其他 launch include。 |
| launch/rviz.launch | 只打开 RViz 健康界面，不启动监控规则。 |
| launch/health_monitor_v2.launch | V2健康监控节点配置入口，供其他组合入口复用。 |
| launch/replay.launch | rosbag受管回放入口，可组合启动健康节点与RViz，并在播放正常结束后封存日志。 |
| launch/recorded_bag_health.launch | 已录制雷达/IMU/定位结果的回放检查入口。 |
| launch/recorded_bag_range_health.launch | 使用带可选测距配置的回放组合入口。 |

## 10. FAST-LIO与Livox驱动源码入口

以下是仓库两个独立工程中最常查看的代码位置：

| 路径 | 作用 |
| --- | --- |
| FAST_LIO/src/laserMapping.cpp | FAST-LIO主节点；接入点云和IMU、执行激光惯性状态估计、维护局部地图并发布定位/地图结果。 |
| FAST_LIO/src/IMU_Processing.hpp | IMU时间同步、去畸变与状态预测相关处理。 |
| FAST_LIO/src/preprocess.cpp 与 preprocess.h | 雷达点云预处理及不同雷达数据格式处理。 |
| FAST_LIO/include/ikd-Tree/ikd_Tree.cpp 与 ikd_Tree.h | 增量式 KD-tree 地图维护、近邻查询和点更新。 |
| FAST_LIO/include/common_lib.h | FAST-LIO共享数据类型、状态和常用定义。 |
| FAST_LIO/include/so3_math.h、Exp_mat.h、use-ikfom.hpp | SO(3)旋转、指数映射及IKFoM状态/滤波接口工具。 |
| FAST_LIO/include/IKFoM_toolkit/ | 流形状态表示及误差状态卡尔曼滤波模板实现。 |
| livox_ros_driver/livox_ros_driver/livox_ros_driver/ | Livox ROS数据接入、设备实例和数据发布实现；例如 lddc 处理ROS发布，lds 管理设备数据源，lds_lidar/lds_lvx 分别处理设备流与LVX文件。 |
| livox_ros_driver/livox_ros_driver/common/comm/ | Livox设备通信、GPS和SDK协议解析。 |
| livox_ros_driver/livox_ros_driver/timesync/ | 驱动时间同步实现。 |
| livox_ros_driver/livox_ros_driver/common/rapidjson/ 与 rapidxml/ | 随驱动源码携带的第三方JSON/XML头文件。 |

第三方 RapidJSON、RapidXML 和 IKFoM 文件数量较多，按其上游库整体说明；本模块的逐文件清单见第2至9节。FAST-LIO和Livox驱动继续使用各自目录中的README与许可证。

## 11. 健康检测数据流

~~~text
health_robot.yaml / health_bag.yaml
        ↓ ConfigLoader校验并加载 enabled 规则
ROS Topic → input_adapters.cpp → 统一 Sample
                                      ↓
                         StreamTracker + 各 C++ Checker
                                      ↓
                           RuleLatch + 生命周期判断
                                      ↓
                               ModuleMonitor
                                      ↓
                          总体状态 / ModuleReport
                           ↙          ↓          ↘
                  ROS diagnostics  EventRecorder  RViz HealthPanel
                                    JSONL/CSV      只呈现诊断
~~~

阅读代码时建议按数据流顺序查看：先看所用 YAML；再看 input_adapters.cpp 中消息映射和单位转换；随后在 health_core.cpp 找具体规则；最后看 robot_health_monitor_node.cpp 发布结果，以及 event_recorder.cpp 和 health_panel.cpp 如何保存、呈现结果。
