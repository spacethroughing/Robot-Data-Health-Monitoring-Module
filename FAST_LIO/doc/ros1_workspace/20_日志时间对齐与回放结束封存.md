# 20 日志时间对齐与回放结束封存

更新日期：2026-10-15（Asia/Shanghai）。

## 1. 本次需求与范围

用户要求日志时间能对应bag中的时间，并在包正常播完后自动结束记录。功能使用C++实现，现有 `recorded_bag_health.launch` 默认启用自动封存。界面和控制心跳继续保留，Ctrl+C仍用于关闭整套launch。

本次未改健康阈值、原始bag、修复副本或历史日志。新格式仅用于重启之后的新run，历史7af80、7cae4日志仍保留原样。

## 2. 当前日志只保留三种时间（2026-10-15更新）

| 字段 | 含义 | 使用方式 |
| --- | --- | --- |
| `bag_elapsed_sec` | 事件入队时当前ROS `/clock` 减去bag元数据起始记录时间 | 看“包播放到第几秒”；当前副本约0～286.37秒 |
| `source_stamp_sec` | 当前事件关联消息的原始 `header.stamp`，单位秒 | 分析STAMP_GAP、无效时间戳和源数据；无消息关联时为null |
| `steady_elapsed_sec` | 当前进程日志记录器创建以来经过的单调秒数 | 分析超时、消抖与恢复保持时间；包含初始化/暂停/EOF等待 |

JSONL与CSV均只输出上述三个时间字段。移除 `bag_time_sec/ns/local/utc`、`source_stamp_ns`、`wall_time_utc`，以及上下文/指标中的重复 `last_stamp_sec` 和源时间别名。源时间统一放在顶层/独立CSV列。播放器上下文不再重复保存绝对回放时钟与结束时刻。**接收年龄age_sec、时间戳间隔、延迟等检测指标是检测结果，继续保留。**

运行清单 `manifest.json` 保留bag起止时刻这一固定元数据及配置/代码/bag哈希，用于复核bag进度的计算依据；它们不作为每条事件的额外时间列。历史日志不追改。

### 不能混淆的边界

- `bag_elapsed_sec` 来自**当前 `/clock`**，受时钟发布频率和回调处理时刻影响，不保证精确等于该消息在bag内逐条记录的record time减去起点，也不保证等于源时间减起点。
- `source_stamp_sec` 保留消息头原值；接收超时事件中仍是最后一条消息的时间，不表示新收到数据。无效0保留0；设备相对时间不强行转为日期。
- `/clock` 尚未就绪、没有有效bag元数据或超出已知范围时，`bag_elapsed_sec` 为null；没有消息关联的 `source_stamp_sec` 也为null。CSV对应单元格为空。
- 源时间内部仍用整数秒+9位纳秒格式化，再输出秒数；不改变阈值/运动计算。JSON消费者如果解析为双精度浮点，Unix大时间戳不能保证纳秒无损，精确原值仍可回查bag。
- 暂停时bag进度不动，单调时间继续走；2倍速时bag进度走得更快。RECEIVE_AGE使用独立单调计时探针，不能用bag进度替代。
- 健康节点和播放器是两个进程，各自的 `steady_elapsed_sec` 起点独立，不应直接相减当作跨进程延迟。

CSV列顺序：`bag_elapsed_sec,source_stamp_sec,steady_elapsed_sec,module_id,producer_instance_id,epoch,operating_state,health_level,operational_valid,metrics_json`。JSONL和CSV的时间均在入队时取快照，异步落盘不会重新取时间。

## 3. 正常播完后自动封存

当前默认入口的流程：

1. C++回放控制器沿用原生退出码与时钟到文件末尾的双重EOF核对，提前退出不能伪装成完成。
2. 发出最终STOPPED控制状态，写入 `PLAYBACK_COMPLETED`。
3. 回放控制日志写入 `RUN_END`，排空队列，刷新/同步并关闭文件。
4. 健康节点接收专用 `/recorded_bag_playback/state`，核对发布节点、非latched、bag路径、正常退出与明确EOF原因；同时等待必需模块已接受同一控制run/实例的STOPPED。
5. 健康日志保存各模块最后一组指标，写入 `RUN_END`，排空队列，刷新/同步并关闭文件。
6. 此后即使窗口继续开着，结构化JSONL/CSV也不再追加；关闭窗口不会再往这份日志补第二个RUN_END。

两个进程各自完成封存，不是一个跨进程原子操作。正常关闭为幂等，失败会继续显示日志异常，不将写入失败当成正常封存。

### 其他状态

- PAUSED：不封存，继续记录暂停/恢复过程。
- FAULT、提前退出、断流或未能证明EOF：不按正常完播自动封存，继续保留故障追溯；程序关闭时仍会正常结束其日志。
- 手动STOP或其他控制器的STOPPED：不等同于本次受监督播放器的verified EOF。
- EOF后正常封存：`logs_finished=true`、`logs_recording=false`、`log_recording_state=FINISHED`；如果此前没有记录缺失，`logs_normal`仍可为true，不能因为主动结束记录就显示日志故障。
- RViz会新增“日志记录：已结束”，原“日志正常：True/False”继续表示记录完整性。
- 一份封存日志对应一次回放。要重新播放/换包，请重启launch创建新run；本次不实现封存后自动重新打开旧文件。

## 4. 启动与开关

原启动命令继续使用：

```bash
bash -c '
source /opt/ros/noetic/setup.bash &&
source $HOME/fastlio_ws/devel/setup.bash &&
export ROS_MASTER_URI=http://127.0.0.1:33522 &&
exec roslaunch -p 33522 fastlio_health_monitor recorded_bag_health.launch
'
```

默认 `finish_log_on_playback_complete:=true`。需要让日志继续记录EOF之后的节点状态时，在roslaunch命令末尾传：

```text
finish_log_on_playback_complete:=false
```

这是launch参数，不是健康YAML中的阈值字段。`health_v2_rslidar_mavros.yaml`仍是健康检测配置，用户已调整的IMU源间隔/接收年龄参数均保留。

通用 `health_monitor_v2.launch` 的自动封存默认false；只有传入自动封存参数和专用播放状态topic时才启用，避免把实机正常停定位当作结束整份监控日志。未配置封存的其他入口仍按原方式记录到节点退出。启用bag时间需要 `/use_sim_time=true`、有效bag数据引用和可读索引。

日志位置仍为：

```text
$HOME/fastlio_ws/logs/robot_health/<run_id>/
$HOME/fastlio_ws/logs/robot_playback/<run_id>/
```

## 5. 实现与验证状态

- `EventRecorder` 增加ROS无关的 `LogTimeline` 时间提供器，以及显式、幂等的 `finish()`。封存期间拒收后续记录但不将其计作丢失；最后等待写线程排空并关闭文件。
- `bag_log_timeline.h` 是ROS侧只读元数据/时钟适配，不给核心记录器引入ROS依赖；bag打不开时仍允许写现实/单调时间的故障日志。
- 输入适配器保留精确消息头纳秒；健康节点和回放节点分别处理封存，RuntimeState消息格式未改。
- CMake声明公开ROS bag相关依赖，健康节点、回放节点、运行控制器、核心库和面板均重新编译。
- 修改前备份及构建日志：`$HOME/fastlio_ws/优化备份/20261015_before_bag_time_log_finish/`；构建日志同步到 build.log（本机测试归档，未纳入仓库）。

### 已知边界

自动封存发生在**确认正常EOF之后**。此前第19篇记录的约0.5～0.64秒EOF确认空窗及其中接收超时事件，没有在本次修改中被删除或声称消除。封存会保留已经产生的告警，停止其后的持续记录；它与进一步优化EOF过渡瞬时误报是两项工作。

JSONL源事件时间和CSV时间为排入日志队列时的快照，不在写线程真正落盘时重新取bag时间。保留单调时间以区分EOF时bag时间冻结但现实告警持续升级的情况。
