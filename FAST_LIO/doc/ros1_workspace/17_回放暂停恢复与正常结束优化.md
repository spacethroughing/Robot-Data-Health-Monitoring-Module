# 回放暂停、恢复与正常结束优化

更新日期：2026-10-14。适用：当前C++ V2及一键/managed回放入口。原始bag和用户健康检测阈值未修改。

## 一、现在的行为

| 操作或事件 | RViz运行状态 | 数据要求 |
|---|---|---|
| 正常回放 | STARTING → RUNNING | 检查雷达、IMU、定位的超时和质量 |
| 在启动终端按空格 | PAUSED，灰色 | 确认暂停后，暂停输入与依赖定位输出的持续数据要求 |
| 再按空格 | STARTING → RUNNING | 重新确认数据就绪，恢复检测 |
| 正常播放到文件末尾 | STOPPED，灰色 | 回放任务结束，保留节点和最后地图，持续发送状态心跳 |
| bag内部真实IMU断流 | ERROR | 播放器仍在RUNNING，不能把它当成用户暂停 |
| 播放器提前退出或异常退出 | FAULT / ERROR | 不作为正常EOF |
| 回放状态通道失联 | UNKNOWN / ERROR或控制器报告FAULT | 不永久相信上一次暂停/停止通知 |
| 定位节点意外退出 | FAULT / ERROR | 暂停/EOF不能覆盖实际节点故障 |

暂停是PAUSED，文件播放完是STOPPED；二者是独立的生命周期。暂停/停止时业务有效性为false，不冒充正在提供有效定位的OK。旧UInt8及标准诊断兼容等级保留WARNING=1，界面使用灰色生命周期徽标；真正故障仍优先ERROR=2。

暂停时最后一份指标及地图可以保留；接收年龄仍可增长，这是显示最后接收时间，不代表暂停期间仍要求连续数据。实际收到的严重坏消息仍按原质量规则报错。

## 二、启动命令

结束此前运行的旧launch，再整段复制执行。启动命令与用户此前使用的一致，新编译节点会自动接入状态桥接：

```bash
bash -c '
source /opt/ros/noetic/setup.bash &&
source $HOME/fastlio_ws/devel/setup.bash &&
exec roslaunch fastlio_health_monitor visualization_bag_testbench.launch \
  bag:=$HOME/datasets/fastlio/health_fault_cases/imu_watchdog_20261014/imu_source_scheduled_silence_1s_150ms.bag \
  health_config:=$HOME/fastlio_ws/src/fastlio_health_monitor/config/health_v2_avia.yaml \
  rate:=1.0 \
  rviz:=true
'
```

启动就绪后在这个终端按空格暂停/恢复。EOF后按Ctrl+C关闭整套程序；从头再次回放要重新启动整套launch，不能把旧定位滤波器直接接到回退的bag时间。

如果启动环境没有可用交互终端，用包装器的确认服务：

```bash
# 先在另一个Bash终端加载ROS和工作区环境。
rosservice call /fastlio_bag_playback/pause "{data: true}"
rosservice call /fastlio_bag_playback/pause "{data: false}"
```

支持的是一键入口内的包装器服务。独立手工执行 `rosbag play` 不会自动告知本监控生命周期；单纯发现 `/clock` 停住不足以推断正常暂停。直接操作底层 `/fastlio_test_bag_player/pause_playback` 会绕过包装器意图同步，日常使用应操作空格或上述包装器服务。

## 三、C++如何实现

1. `health_bag_playback_node`仍确认FAST-LIO和监控均已订阅，再检查实际TCPROS连接后起播。
2. 包装器管理真实终端的空格，原生rosbag使用独立PTY作为stdin，避免两个进程竞争同一个空格。空格和包装器SetBool服务走同一条暂停/恢复路径。
3. 底层rosbag暂停服务确认成功后，发送非latched的RuntimeState和持续心跳。没有使用“数据没来”或“时钟不动”猜测暂停。
4. 普通一键入口的包装器根据实际健康YAML提取控制topic及bindings，向雷达/IMU和定位发送相应意图。EOF后包装器常驻，避免旧STOP通知因失联被当成可信状态。
5. managed入口保持运行控制器拥有公共状态topic：通过`/managed_bag_playback/state`获取源状态，配置`playback_state_topic`和`suspend_output_bindings`，同步数据与依赖输出的暂停/停用。两种入口不会让两个控制器同时争抢公共状态。
6. 正常EOF必须满足：原生播放器退出码0，并且该播放器的 `/clock` 已接近bag文件末尾（50ms粒度容差）。给最后的时钟回调最多100ms确认时间，短暂STOPPING后确认STOPPED。提前`rosnode kill`可能也返回0，不能只凭退出码认定完成。
7. 包装器检查实际mapping节点XMLRPC存活；managed配置新增`supervised_ros_node: /laserMapping`，运行控制器同时检查实际ROS节点，不能只相信外层roslaunch还活着。实际节点故障优先于依赖暂停/停止。
8. 暂停/停止确认替代旧数据要求造成的运行故障；当前心跳丢失、日志故障、严重坏数据仍重新检查。恢复时同一实例不回退时间戳或伪造新定位实例。
9. 总体诊断增加PAUSED/STOPPED聚合状态，面板已有灰色徽标。每个模块增加运行状态原因，帮助区分有意停用与故障。

涉及源码：[bag_playback_node.cpp](../../../fastlio_health_monitor/src/bag_playback_node.cpp)、[runtime_controller_node.cpp](../../../fastlio_health_monitor/src/runtime_controller_node.cpp)、[health_core.cpp](../../../fastlio_health_monitor/src/health_core.cpp)、[robot_health_monitor_node.cpp](../../../fastlio_health_monitor/src/robot_health_monitor_node.cpp)、[health_panel.cpp](../../../fastlio_health_monitor/src/health_panel.cpp)。

另修正ConfigLoader的YAML节点别名赋值：使用reset重绑定控制/日志节点，避免有效配置的monitor字段被覆盖成control字段。原始配置及阈值未修改。

## 四、日志路径与可追溯事件

- 健康监控：`$HOME/fastlio_ws/logs/robot_health/<run-id>/`。
- 回放包装器：`$HOME/fastlio_ws/logs/robot_playback/<run-id>/`。普通入口可以用`playback_log_directory:=/路径`调整。
- managed控制器：`$HOME/fastlio_ws/logs/robot_runtime/<run-id>/`。

包装器事件包括PLAYBACK_STARTING、PLAYBACK_PAUSED、PLAYBACK_RESUMED、PLAYBACK_VERIFYING_EOF、PLAYBACK_COMPLETED、PLAYBACK_FAILED、MAPPING_NODE_LOST。事件记录command_id、原生退出码、任务结果码、最后播放器时钟、bag末尾时间、数据引用和配置/二进制哈希。

监控通过CONTROL_INTENT/STATE_CHANGED关联生命周期；managed控制器记录PLAYBACK_SOURCE_CHANGED、ROS_NODE_LOST及进程退出事件。普通入口诊断的controller_log_directory指向包装器日志；managed指向运行控制器日志。

沿用之前授权的错误bag测试，本次仅使用当前配置做暂停/恢复/EOF功能验收，没有做阈值对比实验，也没有重新制作此前视频。

- 普通一键入口：真实PTY发送空格，暂停保持3.3秒，恢复后继续完整回放；14项检查通过。错误bag内部仍产生接收超时ERROR；EOF保持3.3秒以上不报断流错误；停止状态发送端后监控转UNKNOWN/ERROR。
- managed入口：同样真实空格操作，暂停和恢复、真实错误、EOF保持均通过；EOF后主动关闭定位节点会转FAULT/ERROR，证明不会被正常结束状态覆盖。11项检查通过。

- 有效配置monitor包含正确publish_rate_hz/soft_warning_hold_sec，不再含错位的strict_intent；原用户健康配置值保持100Hz、消抖0、IMU0.1/0.2秒。
