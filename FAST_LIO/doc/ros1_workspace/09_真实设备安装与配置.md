## 1. 本机与新机器的使用方式

当前工程已经位于 `$HOME/fastlio_ws`，`FAST_LIO`、`livox_ros_driver` 和 `fastlio_health_monitor` 都已在该工作空间中。当前电脑无需重新 clone；按第 2 节加载环境、第 4 节检查/编译即可。

新装机器推荐 Ubuntu 20.04 + ROS Noetic，以匹配当前工程。ROS Noetic 已于 2025-05-31 结束上游支持；新机器安装时请查看 ROS 官方安装页面和维护状态，使用适合该系统的官方仓库/归档说明。依赖和工作空间命令如下，安装 ROS 本身后再继续本手册。

官方参考：[ROS 安装页](https://www.ros.org/install/)、[Noetic 生命周期公告](https://discourse.ros.org/t/ros-noetic-end-of-life-may-31-2025/43160)、[FAST-LIO 上游 README](https://github.com/hku-mars/FAST_LIO)。

## 2. 每个终端的 ROS 环境

本机终端默认是 zsh。每次新开终端，先输入 `bash` 回车进入 Bash；如果已经在 Bash 中则跳过这一行。然后逐行执行：

```bash
source /opt/ros/noetic/setup.bash
source $HOME/fastlio_ws/devel/setup.bash
```

`source` 成功通常不会打印内容。检查包是否可见：

```bash
rospack find fast_lio
rospack find livox_ros_driver
rospack find fastlio_health_monitor
```

如果还没编译过，`devel/setup.bash` 暂时不存在：先只执行 `source /opt/ros/noetic/setup.bash`，完成第 4 节编译后，再加载工作空间 setup。

## 3. 系统依赖与 Livox SDK

### 3.1 Ubuntu/ROS 依赖

在 Ubuntu 20.04 新机器上，先按 ROS 官方安装页配置软件源/密钥，再安装 ROS Noetic Desktop Full：

```bash
sudo apt update
sudo apt install -y ros-noetic-desktop-full
```

然后安装项目构建依赖：

```bash
sudo apt update
sudo apt install -y \
  build-essential cmake git \
  python3-rosdep \
  libapr1-dev libboost-all-dev \
  libeigen3-dev libpcl-dev
```

ROS Desktop Full 提供 RViz 及常用 ROS 工具。首次使用 `rosdep` 时初始化一次；已初始化过就跳过 `rosdep init`：

```bash
sudo rosdep init
rosdep update
```

### 3.2 安装 Livox-SDK

`livox_ros_driver` 需要系统安装 Livox-SDK。若 `/usr/local/lib/liblivox_sdk_static.a` 已存在，可跳过 SDK 编译；否则：

```bash
cd /tmp
git clone https://github.com/Livox-SDK/Livox-SDK.git
cd /tmp/Livox-SDK/build
cmake ..
make -j2
sudo make install
sudo ldconfig
```

确认静态库：

```bash
ls -l /usr/local/lib/liblivox_sdk_static.a
```

上游安装参考：[Livox-SDK README](https://github.com/Livox-SDK/Livox-SDK)。不要在 Catkin 工作区里用 `sudo catkin_make`；只有系统 SDK 安装步骤使用 sudo。

## 4. Catkin 工作包获取、依赖安装和编译

### 4.1 当前工作区

本机源码位置如下：

| ROS 包 | 源码路径 |
|---|---|
| FAST-LIO（ROS 包名 `fast_lio`） | `$HOME/fastlio_ws/src/FAST_LIO` |
| Livox ROS Driver | `$HOME/fastlio_ws/src/livox_ros_driver/livox_ros_driver` |
| 健康监控与 RViz 面板 | `$HOME/fastlio_ws/src/fastlio_health_monitor` |

ROS 包是放在工作空间 `src/` 下、带有 `package.xml` 的 Catkin 包。当前 Livox 驱动仓库在仓库子目录中包含 ROS 包，因此不要把它里面的 ROS 包再重复 clone 到另一个目录。

### 4.2 新机器克隆上游工程

以下仅用于新建的空工作区。健康监控包是本项目的本地 C++ 包；需将本项目的 `src/fastlio_health_monitor` 复制/同步到新机器的工作空间，当前没有假设一个未提供的公开 Git 地址。

```bash
mkdir -p ~/fastlio_ws/src
cd ~/fastlio_ws/src
git clone https://github.com/Livox-SDK/livox_ros_driver.git
git clone https://github.com/hku-mars/FAST_LIO.git
cd FAST_LIO
git submodule update --init --recursive
```

将本项目的 `fastlio_health_monitor` 目录放到 `~/fastlio_ws/src/fastlio_health_monitor` 后继续。确保目录结构类似：

```text
~/fastlio_ws/src/FAST_LIO/package.xml
~/fastlio_ws/src/livox_ros_driver/livox_ros_driver/package.xml
~/fastlio_ws/src/fastlio_health_monitor/package.xml
```

### 4.3 安装 ROS 包依赖并编译

当前工作区和新建工作区都在 ROS 环境加载后执行：

```bash
source /opt/ros/noetic/setup.bash
cd $HOME/fastlio_ws
rosdep install --from-paths src --ignore-src -r -y --rosdistro noetic
catkin_make -j2
source $HOME/fastlio_ws/devel/setup.bash
```

新机器若使用 `~/fastlio_ws`，把命令中的 `$HOME/fastlio_ws` 替换为 `~/fastlio_ws` 对应的绝对路径。日常修改 YAML/launch 不需要重编译；改动 C++ 后重新执行 `catkin_make -j2`，再在所有新终端 source 工作空间。

验证编译产物与 ROS 包索引：

```bash
rospack find fast_lio
rospack find livox_ros_driver
rospack find fastlio_health_monitor
```

## 5. 真实设备网络与 Livox 驱动

### 5.1 网线、网卡和地址

将 Avia 接到电脑以太网口，供电并确认设备工作。先查看网卡名、当前地址和路由：

```bash
ip -br link
ip -br addr
ip route
```

按照 **Avia 对应版本的设备手册/设备管理工具** 设置雷达和电脑有线网卡地址，使两者位于可互通的网段且 IP 不冲突。网卡名、雷达 IP、掩码和是否需要静态地址取决于现场网络；本手册不预填固定 IP。确认链路正常后，可用现场雷达 IP 做连通性检查：

```bash
sudo ip link set dev <有线网卡名> up
sudo ip addr add <电脑静态IP>/<CIDR前缀> dev <有线网卡名>
ip -br addr show dev <有线网卡名>
ping <雷达当前IP>
```

尖括号均需替换为现场值；`ip addr add` 设置的是临时地址，重启后失效。永久地址应在 Ubuntu 网络设置/Netplan 中按设备手册配置；不要对正在 SSH 使用或承载其他网络的接口执行清空地址操作。

ROS 节点都运行在同一台电脑时，一般不必手动设置 `ROS_MASTER_URI` 或 `ROS_IP`。若驱动、FAST-LIO 和 RViz 分布在不同电脑，在每台机器 source 环境后按实际地址设置：

```bash
export ROS_MASTER_URI=http://<ROS主机IP>:11311
export ROS_IP=<本机在ROS网段的IP>
```

所有机器使用同一个 `ROS_MASTER_URI`，各自的 `ROS_IP` 必须是彼此可达的地址；还需确认主机名解析/防火墙允许 ROS TCPROS 连接。

### 5.2 广播码与 JSON

编辑当前驱动读取的配置文件：

```bash
nano $HOME/fastlio_ws/src/livox_ros_driver/livox_ros_driver/config/livox_lidar_config.json
```

把机身二维码下的实际 **15 位广播码** 填到对应 `broadcast_code`，只将目标 Avia 的 `enable_connect` 设为 `true`，其他设备设为 `false`。本工作区 JSON 中目前有两条示例广播码且都为 `false`，需要按现场设备改成真实值；不要把示例码当作本机雷达序列号。Livox 驱动文档说明广播码用于指定设备，全部设为 false 时驱动会进入自动连接模式。[Livox ROS Driver 配置说明](https://github.com/Livox-SDK/livox_ros_driver/blob/master/README_CN.md)

配置 JSON 片段示意（尖括号内容需要替换，不能原样保存）：

```json
{
  "lidar_config": [
    {
      "broadcast_code": "<机身上的15位实际广播码>",
      "enable_connect": true,
      "return_mode": 0,
      "coordinate": 0,
      "imu_rate": 0,
      "extrinsic_parameter_source": 0
    }
  ],
  "timesync_config": {
    "enable_timesync": false,
    "device_name": "/dev/ttyUSB0",
    "comm_device_type": 0,
    "baudrate_index": 2,
    "parity_index": 0
  }
}
```

保留当前 Avia 驱动支持的回波、坐标和 IMU 设置；不要照抄其他型号的 `imu_rate`。先按当前值启动并用 `/livox/imu` 实测频率，确需修改时依据对应型号/固件的 Livox 文档。

### 5.3 驱动启动

当前 `livox_lidar_msg.launch` 将 `xfer_format` 设为 `1`，输出 FAST-LIO Avia 需要的 `livox_ros_driver/CustomMsg`，发布频率默认为 10 Hz。此 launch 的 `bd_list` 默认值是示例占位串，驱动代码会把它判为非法并打印提示。启动时显式清空该参数，让实际设备选择只由 JSON 控制：

```bash
roslaunch livox_ros_driver livox_lidar_msg.launch bd_list:=""
```

保持这个终端运行。驱动日志应显示配置文件路径、SDK/设备发现与连接信息；不应把 `Invalid bd:100000000000000` 误认为真实设备码。若出现连接失败，先检查广播码、网线、网卡地址和子网，再检查 JSON 是否有效。

## 6. FAST-LIO 与健康监控参数

### 6.1 FAST-LIO Avia 参数

检测台通过 `mapping_avia.launch` 加载：

```text
$HOME/fastlio_ws/src/FAST_LIO/config/avia.yaml
```

重点参数如下。topic 要与驱动发布一致；外参必须来自传感器安装测量或标定结果，不要把示例值当作任意设备的标定值。

| YAML 字段 | 当前 Avia 值 | 作用/修改要求 |
|---|---:|---|
| `common.lid_topic` | `/livox/lidar` | LiDAR CustomMsg 输入 topic |
| `common.imu_topic` | `/livox/imu` | IMU 输入 topic |
| `common.time_sync_en` | `false` | 仅外部时间同步确实无法实现时再考虑软件同步 |
| `common.time_offset_lidar_to_imu` | `0.0` | 标定的 LiDAR-IMU 时间偏置，单位秒 |
| `preprocess.lidar_type` | `1` | Livox 系列类型 |
| `preprocess.scan_line` | `6` | 当前 Avia 配置值 |
| `preprocess.blind` | `4` | 近距离盲区，单位米 |
| `mapping.extrinsic_est_en` | `false` | 已有可靠外参时关闭在线估计 |
| `mapping.extrinsic_T` | `[0.04165, 0.02326, -0.0284]` | LiDAR 在 IMU/body 坐标系下的位置，米；按现场标定修改 |
| `mapping.extrinsic_R` | 单位矩阵 | LiDAR 在 IMU/body 坐标系下的旋转矩阵；按现场标定修改 |

FAST-LIO 的 Avia 外参定义为 **LiDAR 位姿在 IMU/body 坐标系中的表示**。检测台的 `visualization_testbench.launch` 另有静态 TF `body -> livox_raw`，当前平移也是 `[0.04165, 0.02326, -0.0284]`、单位旋转；更改 FAST-LIO 外参后，必须同步更新该静态 TF。上游也建议在已有外参时关闭 `extrinsic_est_en`，并仅在确实无法外部同步时启用软件时间同步。[FAST-LIO Avia 参数说明](https://github.com/hku-mars/FAST_LIO#31-for-avia)

`publish.path_en`、`pcd_save.pcd_save_en` 等映射/发布参数在检测台 launch 中会覆盖成适合实时显示的设置；检测台关闭 PCD 自动落盘，累积地图由 `/Laser_map` 按需发布。修改参数后重新启动对应 launch。

### 6.2 健康监控 YAML

Avia 检测台读取：

```text
$HOME/fastlio_ws/src/fastlio_health_monitor/config/avia.yaml
```

当前 topic 为 `/livox/lidar`、`/livox/imu`、`/Odometry`。Livox SDK 的加速度输入以 `g` 表示，因此 `imu_acceleration_unit: "g"`；监控 C++ 节点换算后按 m/s² 判断和显示。若 IMU 实际消息已是 m/s²，则改为 `"mps2"`，不可重复乘重力常数。

可按设备频率和现场数据调整 `minimum_lidar_rate_hz`、`minimum_imu_rate_hz`、`minimum_lidar_points`、`minimum_valid_point_ratio`，以及 `*_stale_warning_sec` / `*_stale_error_sec`。加速度阈值 `maximum_acceleration_mps2` 始终以 m/s² 设置，角速度阈值以 rad/s 设置。启动后改 YAML 需要重启节点，不需要重新编译 C++。

## 7. 完整实机启动顺序

确保设备网络/广播码已配置，且所有终端加载同一工作区环境。若当前是 zsh，分别在每个终端先输入 `bash`。

### 终端 1：Livox 设备驱动

```bash
source /opt/ros/noetic/setup.bash
source $HOME/fastlio_ws/devel/setup.bash
roslaunch livox_ros_driver livox_lidar_msg.launch bd_list:=""
```

### 终端 2：FAST-LIO + 健康监控 + RViz 检测台

```bash
source /opt/ros/noetic/setup.bash
source $HOME/fastlio_ws/devel/setup.bash
roslaunch fastlio_health_monitor visualization_testbench.launch
```

`roslaunch` 会在当前 ROS master 不存在时启动它；不需要额外开 roscore。终端 1 和终端 2 必须连接到同一 ROS master。真实设备使用墙钟，不能同时启动 bag 回放入口。

### 终端 3：检查输入、定位和健康状态

```bash
source /opt/ros/noetic/setup.bash
source $HOME/fastlio_ws/devel/setup.bash
rostopic type /livox/lidar
rostopic hz /livox/lidar
rostopic hz /livox/imu
rostopic echo -n 1 /Odometry
rostopic echo -n 1 /fastlio_health_monitor/status
rostopic echo -n 1 /fastlio_health_monitor/diagnostics
rosrun tf tf_echo camera_init livox_raw
```

期望 `/livox/lidar` 类型为 `livox_ros_driver/CustomMsg`；LiDAR、IMU 和 Odometry 都持续更新；健康状态按输入质量显示 `0=OK`、`1=WARNING`、`2=ERROR`。RViz Fixed Frame 为 `camera_init`，查看健康面板、原始点云、`/cloud_registered` 当前帧和 `/Laser_map` 累积地图。刚启动时尚未收到足够数据，短暂 ERROR/无地图属初始化阶段；持续 ERROR 时从对应诊断原因开始排查。

正常关闭时先在终端 2 按 `Ctrl+C` 结束检测台，再在终端 1 按 `Ctrl+C` 结束驱动。

## 8. 常见启动失败检查

| 现象 | 处理顺序 |
|---|---|
| `rospack find` 找不到包 | source Noetic 和工作区 setup；确认编译成功、`package.xml` 位于 `src` 下 |
| Livox 没连接 | 检查以太网 link/IP/子网、设备供电、JSON 内目标广播码及 `enable_connect: true`；启动命令带 `bd_list:=""` |
| 驱动连上但 FAST-LIO 没数据 | 检查 `/livox/lidar` 类型是否为 CustomMsg、`/livox/imu` 是否持续发布，以及两端是否同 ROS master |
| 有原始输入但无定位 | 检查 `common.*_topic`、IMU/LiDAR 时间戳、Avia YAML 预处理参数和实测外参 |
| TF 外参和点云显示不一致 | 同步 FAST-LIO `extrinsic_T/R` 与检测台 launch 静态 `body -> livox_raw`；重新启动 |
| IMU 状态异常或加速度过大 | 确认实际消息单位；Avia SDK 输入用 `g`，m/s² 输入用 `mps2`，避免重复换算 |
| 回放和实机结果混杂 | 关闭其中一种输入；真实设备模式不要同时运行 rosbag player |

更多 RViz 图层、launch 参数、bag 回放和截图说明见[06_启动与操作说明](06_启动与操作说明.md)，健康判定与代码入口见[04_代码说明](04_代码说明.md)。
