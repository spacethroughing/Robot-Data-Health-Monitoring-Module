## ROS 接口

### 输入

| 参数 | 默认值 | 消息类型 | 用途 |
|---|---|---|---|
| `lidar_topic` | `/livox/lidar` | `livox_ros_driver/CustomMsg` 或 `sensor_msgs/PointCloud2` | 雷达输入；由 `lidar_type` 选择消息类型 |
| `lidar_type` | `livox_custom` | 字符串参数 | 可选 `livox_custom`、`pointcloud2` |
| `lidar_visualization_topic` | `lidar_raw_visualization` | 字符串参数 | 私有命名空间下的原始点云可视化输出 topic |
| `lidar_visualization_frame` | `livox_raw` | 字符串参数 | 显示消息的 frame_id；空值保持输入 frame；改名本身不变换点坐标，须配置匹配 TF |
| `imu_topic` | `/livox/imu` | `sensor_msgs/Imu` | IMU 输入 |
| `imu_acceleration_unit` | `g`（节点/Avia）；PointCloud2 示例为 `mps2` | 字符串参数 | 独立选择 IMU 输入加速度单位，仅允许 `g`、`mps2`；不从雷达类型推断 |
| `odometry_topic` | `/Odometry` | `nav_msgs/Odometry` | FAST-LIO 定位输出 |

### 输出

| Topic | 类型 | 说明 |
|---|---|---|
| `/fastlio_health_monitor/diagnostics` | `diagnostic_msgs/DiagnosticArray` | 总体、雷达、IMU、定位四项；状态按 ROS DiagnosticStatus 标准 |
| `/fastlio_health_monitor/status` | `std_msgs/UInt8` | 总体码：0 OK、1 WARNING、2 ERROR；latched |
| `/fastlio_health_monitor/lidar_raw_visualization` | `sensor_msgs/PointCloud2` | 将 Livox `CustomMsg` 转换为 RViz 可显示的 xyz/intensity 原始点云；PointCloud2 输入则透传/按设置复制 |
| `/Laser_map` | `sensor_msgs/PointCloud2` | FAST-LIO 完整地图快照；检测台默认以墙钟 1 Hz 更新且有订阅者时才展开地图；队列 1、latch=true 缓存最新快照；含 intensity 字段供 RViz 着色 |

## 主要实现

- `updateStream` 使用墙钟记录接收时间和窗口频率，避免 ROS 时间暂停时 watchdog 不更新。
- Livox `CustomMsg` 与 PointCloud2 分别有回调；PointCloud2 根据字段偏移、数据类型和字节序读取 xyz，检查缓冲区、非有限值、零距离和最大量程。
- IMU 检查时间戳、线加速度和角速度的有限性及模长。
- Odometry 检查位置/姿态有限性、单位四元数、位姿协方差对角线和相邻位姿速度。
- `ros::WallTimer` 定期计算最新样本质量、接收延迟和输入频率，再发布诊断。
- 每项诊断保留 `sample_status` 和 `sample_message`，所以即便总体被更严重的断流错误提升，最近一帧的质量判断仍可追溯。
- 运行阈值位于 `config/avia.yaml` 和 `config/pointcloud2.yaml`，无需改 C++ 即可适配设备 topic 和频率。
- `health_panel.cpp` 导出 RViz `Panel` 插件，在 Qt 面板中订阅 `DiagnosticArray`，显示总体状态及 LiDAR、IMU、Odometry 的 topic、频率、延迟、质量与位姿指标。
- `visualization_testbench.launch` 一键启动 FAST-LIO、监控器、Avia 静态 TF 和 RViz；`fastlio_health_testbench.rviz` 的原始输入、当前帧、累积 `/Laser_map` 均使用 intensity 彩虹着色，另显示 Odometry、Path、TF 和健康面板。三层 `Decay Time=0` 仅显示最新消息并保持至下一份到达；地图每份消息已经包含整个 k-d tree，无需累积多份快照。
- 地图关闭 `Autocompute Intensity Bounds`，固定显示范围 0–152，使同一 intensity 的颜色不随整图范围变化。地图 `nh.advertise(..., 1, true)` 限制旧快照队列并缓存最新快照，bag 结束后新订阅者也能收到最后一份已发布地图。
- `visualization_bag_testbench.launch` 在检测台基础上设置仿真时间并启动 rosbag player；使用 `--wait-for-subscribers` 等待 LiDAR/IMU 输入订阅就绪，默认 bag 路径和播放速率可通过 launch 参数覆盖。

## 按代码结构理解实现

这套包可以看作两条并行的 C++ 链路：`health_monitor_node.cpp` 读传感器和定位 Topic，完成质量检查并发布诊断；`health_panel.cpp` 订阅诊断并把状态画到 RViz 左侧面板。launch/YAML 只负责选择消息类型、参数、坐标关系和启动组合。

```mermaid
flowchart LR
  L[雷达输入<br/>CustomMsg 或 PointCloud2] --> F[FAST-LIO]
  L --> M[health_monitor_node.cpp<br/>点云质量检查]
  L --> V[原始点云转接<br/>/lidar_raw_visualization]
  I[IMU<br/>sensor_msgs/Imu] --> F
  I --> M
  F --> O[/Odometry<br/>/cloud_registered<br/>/Laser_map<br/>/path]
  O --> M
  M --> D[/diagnostics<br/>总体+LiDAR+IMU+Odometry]
  M --> S[/status<br/>0/1/2]
  D --> P[health_panel.cpp<br/>RViz Qt 面板]
  V --> R[RViz 三维视图]
  O --> R
```

### 2. 构建系统如何生成节点和 RViz 面板

监控节点和 RViz 面板是两个不同的二进制目标：`fastlio_health_monitor_node` 是 ROS 可执行节点；`fastlio_health_monitor_panel` 是由 RViz 动态加载的共享库。面板头文件带有 `Q_OBJECT`，所以 CMake 调用 Qt 的 MOC 生成信号/槽所需代码：

```cmake
qt5_wrap_cpp(HEALTH_PANEL_MOC include/fastlio_health_monitor/health_panel.h)

add_executable(fastlio_health_monitor_node src/health_monitor_node.cpp)
target_link_libraries(fastlio_health_monitor_node ${catkin_LIBRARIES})

add_library(fastlio_health_monitor_panel src/health_panel.cpp ${HEALTH_PANEL_MOC})
target_link_libraries(fastlio_health_monitor_panel ${catkin_LIBRARIES} Qt5::Widgets)
```

`health_panel_plugin.xml` 再声明这个库里导出的 C++ 类：

```xml
<library path="lib/libfastlio_health_monitor_panel">
  <class name="fastlio_health_monitor/HealthPanel"
         type="fastlio_health_monitor::HealthPanel"
         base_class_type="rviz::Panel">
  </class>
</library>
```

`package.xml` 的 RViz export 指向该 XML。RViz 加载 `.rviz` 配置时按插件类名找到描述文件，再加载共享库并实例化 `HealthPanel`。因此“节点正常但面板插件找不到”时，要检查插件目标是否构建、`package.xml` 导出、XML 中的库/类名和终端是否 source 了工作空间。

### 3. 监控节点的启动和输入分流

构造函数使用私有句柄 `private_nh_("~")` 读取监控参数。launch 中将 Avia YAML 放在节点下面加载，参数最终成为节点私有参数，例如 `~lidar_topic` 和 `~imu_acceleration_unit`。节点发布诊断、总状态和原始可视化点云，并按 `lidar_type` 只建立一种 LiDAR 订阅：

```cpp
if (lidar_type_ == "livox_custom") {
  livox_lidar_sub_ = nh_.subscribe(lidar_topic_, 20,
      &FastLioHealthMonitor::livoxLidarCallback, this);
} else if (lidar_type_ == "pointcloud2") {
  pointcloud_lidar_sub_ = nh_.subscribe(lidar_topic_, 20,
      &FastLioHealthMonitor::pointCloudCallback, this);
}
imu_sub_ = nh_.subscribe(imu_topic_, 200,
    &FastLioHealthMonitor::imuCallback, this);
odometry_sub_ = nh_.subscribe(odometry_topic_, 50,
    &FastLioHealthMonitor::odometryCallback, this);
```

IMU 和 Odometry 两路无论雷达格式如何都会订阅。参数选错时 LiDAR 不会收到预期消息；所以 PointCloud2 设备必须同时将 `lidar_type` 设为 `pointcloud2` 并使用与该设备匹配的 FAST-LIO 配置。

### 4. 数据回调：记录“何时收到”并判断“这一帧怎样”

`updateStream()` 是三路输入共享的接收状态更新函数。它使用 `ros::WallTime` 记录本机接收时刻，并单独保留消息头时间戳，用来判断时间戳是否有效、是否严格递增。接收时刻被放进滑动窗口，超出 `rate_window_sec` 的旧记录会移出：

```cpp
const double wall_now = ros::WallTime::now().toSec();
const bool stamp_valid = std::isfinite(stamp) && stamp > 0.0;
state.stamp_monotonic = !state.received ||
    (stamp_valid && (!state.stamp_valid || stamp > state.last_stamp));
state.last_receive_wall = wall_now;
state.receive_times.push_back(wall_now);
while (!state.receive_times.empty() &&
       wall_now - state.receive_times.front() > rate_window_sec_) {
  state.receive_times.pop_front();
}
```

这里特意区分了消息时间和墙钟接收时间：bag 暂停或传感器断流时，墙钟 watchdog 仍能继续发布诊断；位姿速度仍使用 Odometry 的消息时间戳。

#### 4.1 Livox CustomMsg 雷达

`livoxLidarCallback()` 遍历 `msg->points`，每点要求 xyz 都是有限数、距离平方大于 `1e-8` 且不超过 `maximum_point_range_m²`。扫描为空、有效点为零或时间戳无效会进入 ERROR；总点数不足、有效点比例不足、驱动 `point_num` 与数组长度不一致或时间戳不递增会触发 WARNING。该判断不做点云配准，只评价驱动刚发布的原始扫描。

检查完后，`publishLivoxVisualizationCloud()` 将 Livox 自定义消息桥接为 RViz 能直接订阅的 `sensor_msgs/PointCloud2`。主要字段映射如下：

```cpp
modifier.setPointCloud2Fields(4,
    "x", 1, sensor_msgs::PointField::FLOAT32,
    "y", 1, sensor_msgs::PointField::FLOAT32,
    "z", 1, sensor_msgs::PointField::FLOAT32,
    "intensity", 1, sensor_msgs::PointField::FLOAT32);
// Livox CustomPoint 的 reflectivity 映射到 RViz intensity 通道
*x = point.x;
*y = point.y;
*z = point.z;
*intensity = point.reflectivity;
```

可视化 frame 默认设为 `livox_raw`，它只改消息的 `header.frame_id`，不会把 xyz 乘 TF 或改变坐标。launch 里必须提供与 Avia 外参一致的 `body -> livox_raw` TF，RViz 才能把原始扫描放到正确位置。

#### 4.2 通用 PointCloud2 雷达

`pointCloudCallback()` 调用 `inspectPointCloud2()`。函数先查找 `x/y/z` 字段，再验证字段偏移和 datatype 是否落在 `point_step` 范围内，并检查 `row_step`、`height` 和实际 `data` 字节长度。逐点读取时会按消息 `is_bigendian` 与主机字节序决定是否交换字节，因此支持不同字段顺序和大小端数据。xyz 非有限、近零距离和超出最大量程的点均不计为有效点。

结构错误或没有有效点为 ERROR；点数不足或有效率低为 WARNING。可视化输出通常直接透传原消息；若配置了不同的 `lidar_visualization_frame`，代码复制消息并只修改 frame 字段。它同样不执行坐标变换。

#### 4.3 IMU

`imuCallback()` 检查加速度、角速度六个分量的有限性，使用 `std::hypot` 算向量模长。加速度单位由 `imu_acceleration_unit` 明确指定，构造节点时只允许 `g` 或 `mps2`：

```cpp
if (imu_acceleration_unit_ == "g") {
  imu_acceleration_scale_ = 9.80665;
} else if (imu_acceleration_unit_ == "mps2") {
  imu_acceleration_scale_ = 1.0;
} else {
  ROS_FATAL_STREAM(error);
  throw std::invalid_argument(error);
}
// 回调中：先换算再与 m/s^2 阈值比较
const double accel_norm_mps2 = raw_accel_norm * imu_acceleration_scale_;
```

非有限值或无效时间戳是 ERROR；换算后的加速度模长或角速度模长超过配置的物理范围是 WARNING。监控只换算诊断使用的数值，不修改 `/livox/imu` 原消息。

#### 4.4 Odometry 定位输出

`odometryCallback()` 检查位置和四元数有限性、四元数模长、pose covariance 的所有元素及六个对角元素。相邻有效位置通过 `sqrt(dx²+dy²+dz²)/dt` 估计平移速度，`dt` 取消息头时间差。超过 `odometry_warning_speed_mps` 为 WARNING，超过 `odometry_error_speed_mps` 为 ERROR。协方差出现非有限值或负对角线为 ERROR；最大对角线超过阈值为 WARNING。

这些是输出合理性/跳变检查，不是绝对定位精度评估，也不能证明地图无漂移；当前没有真值轨迹参与比较。

### 5. 汇总状态与 ROS 输出

各回调只更新“最近一帧样本”状态；`ros::WallTimer` 周期调用 `publishHealth()`，`evaluate()` 再把最近样本判断、接收年龄、窗口频率和超时组合成分项结果。没有收到过消息直接是 ERROR；至少 3 个接收时刻后才应用最低频率阈值。总体等级取 LiDAR、IMU、Odometry 三者最大值，数值顺序为 `OK=0 < WARNING=1 < ERROR=2`。

诊断中同时写入 `sample_status` 和 `sample_message`，以及当前超时/频率状态。这样一帧点云的 WARNING 在随后传感器断流变成总体 ERROR 时仍可以从诊断键值追溯。最终发布四个 `DiagnosticStatus`（总体和三项）及一个 `UInt8` 总体码：

```cpp
array.status.push_back(makeStatus("FAST-LIO health", "fastlio", summary));
array.status.push_back(makeStatus("FAST-LIO LiDAR input", "lidar", lidar));
array.status.push_back(makeStatus("FAST-LIO IMU input", "imu", imu));
array.status.push_back(makeStatus("FAST-LIO localization output", "odometry", odometry));
diagnostics_pub_.publish(array);
status.data = overall;
status_pub_.publish(status);
```

`DiagnosticArray` 使用标准级别 OK/WARN/ERROR；独立 `/status` 是 latched `std_msgs/UInt8`，刚启动的新订阅者也能立即读到最近总体状态。topic 名称由私有参数 `diagnostics_topic` / `status_topic` 决定；默认完整名称分别为 `/fastlio_health_monitor/diagnostics` 和 `/fastlio_health_monitor/status`。

### 6. RViz 健康面板如何更新

`HealthPanel` 继承 `rviz::Panel`。构造函数用 Qt Layout 建立总体状态、LiDAR、IMU、Odometry 四块显示；`onInitialize()` 订阅 `/fastlio_health_monitor/diagnostics`。回调按 `DiagnosticStatus.name` 找到四个分项，再从 `values` 中读取 topic、频率、有效点数、加速度和位姿键值。

ROS 回调可能不在 Qt GUI 线程执行，因此代码用 `QMetaObject::invokeMethod(..., Qt::QueuedConnection, ...)` 把文本/等级更新排队到 GUI 线程：

```cpp
diagnostics_subscriber_ = node_handle_.subscribe(
    "/fastlio_health_monitor/diagnostics", 10,
    &HealthPanel::diagnosticsCallback, this);
// ROS callback 线程收到新状态后，通过 queued connection 更新 Qt 控件
QMetaObject::invokeMethod(this, "updateLidar", Qt::QueuedConnection,
    Q_ARG(int, lidar_level), Q_ARG(QString, lidar_text));
```

`statusText()` 把 0/1/2 显示为 OK/WARNING/ERROR；`applyStatus()` 根据级别更换徽标文字、前景色和底色。`imuDetails()` 同时显示换算后的 m/s² 与原始值及其单位；因此 Avia 下可看到类似 `8.467 m/s²（原始 0.863 g）`。

### 7. Launch 如何拼装系统

#### 独立监控：`health_monitor.launch`

`config` 默认指向 `config/avia.yaml`。`<rosparam>` 放在节点元素内，因此 YAML 参数进入 `fastlio_health_monitor` 私有命名空间。需要监控其他 PointCloud2 输入时可用 `config:=/绝对路径/pointcloud2.yaml`，但这只启动监控器，不会自动启动相应的 FAST-LIO 或传感器驱动。

#### 实时检测台：`visualization_testbench.launch`

1. 设置 `/use_sim_time`，真实设备默认 `false`。
2. include FAST-LIO 的 `mapping_avia.launch`，关闭 FAST-LIO 自带 RViz，启用 Path 和地图发布、关闭 PCD 自动保存。
3. include `health_monitor.launch`，默认加载 Avia 健康配置。
4. 发布静态 `body -> livox_raw` 外参；当前数字是示例安装外参，须和 FAST-LIO YAML 一起按实际标定核对。
5. 根据 `rviz` 参数启动 RViz，并读取 `rviz_config` 指定的配置文件。

#### 一键回放：`visualization_bag_testbench.launch`

它 include 实时检测台，但强制 `use_sim_time=true`；随后 rosbag player 用 `--clock` 发布仿真时钟，`--wait-for-subscribers` 等待输入订阅者连接再播放。`bag`、`rate` 和 `rviz` 是它对外提供的参数。该入口适合 bag 数据；真实驱动入口不播放 bag。

### 8. RViz 配置如何显示结果

`fastlio_health_testbench.rviz` 通过类名 `fastlio_health_monitor/HealthPanel` 加载 C++ 健康面板；三维区分别订阅原始桥接点云、`/cloud_registered`、`/Laser_map`、`/Odometry`、`/path` 和 TF。Global Fixed Frame 是 `camera_init`。点云以 `intensity` 通道上色；累积地图关闭自动强度范围并固定 0–152，三层 `Decay Time=0` 保留最新消息直到新消息替换。地图消息本身是完整快照，所以 RViz 只要显示最后一份即可。

## 默认阈值与判定

下表对应 `config/avia.yaml`；PointCloud2 示例当前使用相同阈值，输入类型、topic、显示 frame 及 IMU 输入单位配置不同。YAML 在监控节点私有参数空间加载，修改后重新启动监控节点生效。

| 参数 | 默认值 | 判定或用途 |
|---|---:|---|
| `publish_rate_hz` | 2.0 Hz | 墙钟诊断发布频率 |
| `rate_window_sec` | 5.0 s | 新数据到达时维护的接收频率窗口 |
| `lidar_stale_warning_sec` / `lidar_stale_error_sec` | 0.5 / 1.5 s | 接收年龄超过阈值，分别 WARNING / ERROR |
| `imu_stale_warning_sec` / `imu_stale_error_sec` | 0.15 / 0.6 s | 同上，IMU 断流阈值 |
| `odometry_stale_warning_sec` / `odometry_stale_error_sec` | 0.3 / 1.0 s | 同上，定位输出断流阈值 |
| `minimum_lidar_rate_hz` | 5.0 Hz | 至少 3 个窗口样本时，接收频率低于此值为 WARNING |
| `minimum_imu_rate_hz` | 50.0 Hz | 同上，IMU 频率阈值 |
| `minimum_lidar_points` | 100 | 非空扫描的总点数低于此值为 WARNING |
| `minimum_valid_point_ratio` | 0.8 | 有效点比例低于此值为 WARNING；无有效点为 ERROR |
| `maximum_point_range_m` | 500.0 m | 超出量程的点计为无效点 |
| `maximum_acceleration_mps2` | 100.0 m/s² | IMU 加速度模长超过阈值为 WARNING |
| `maximum_angular_velocity_rps` | 35.0 rad/s | IMU 角速度模长超过阈值为 WARNING |
| `odometry_warning_speed_mps` / `odometry_error_speed_mps` | 15.0 / 50.0 m/s | 相邻位姿平移速度超过阈值，分别 WARNING / ERROR |
| `maximum_pose_covariance` | 100.0 | 位姿协方差对角线最大值超过阈值为 WARNING |

固定写在 C++ 中的规则：

- 三路消息头时间戳必须大于 0 且有效，否则 ERROR；不严格递增为 WARNING。
- LiDAR 有效点要求 xyz 有限、距离平方大于 `1e-8` 且不超过最大量程平方。空扫描、无有效点、PointCloud2 字段或缓冲区结构错误为 ERROR；Livox `point_num` 与数组长度不同为 WARNING。
- IMU 线加速度、角速度任一分量非有限，或计算/换算后的模长非有限，为 ERROR。加速度根据 `imu_acceleration_unit` 先统一换算为 m/s² 再与 `maximum_acceleration_mps2` 比较；角速度保持 rad/s。
- 定位位置/姿态非有限、四元数模长小于 `1e-6` 为 ERROR；四元数模长偏离 1 超过 0.02 为 WARNING，超过 0.1 为 ERROR。
- 位姿协方差 36 个元素均需有限、6 个对角元素均需非负，否则 ERROR。该统一经验阈值不能代替各位置/旋转分量的不确定度标定。
- 位姿速度使用消息时间戳差，时间差大于 `1e-4 s` 且存在上一份有效位姿时计算；首帧显示 0 不代表机器人静止。定位项没有单独最低频率阈值，使用断流年龄判断更新情况。

分项状态为最近样本质量与接收超时/频率问题中的最高等级，总体取 LiDAR、IMU、Odometry 的最高等级。`age_sec` 是距离最后收到消息的墙钟时间；`rate_hz` 使用接收时间，bag 倍率会改变它。位姿速度使用消息时间，正常倍率变化不会直接乘算该速度。

## IMU 单位换算（2026-10-10 修复）

节点默认输入为 `/livox/imu`，默认单位为 `g`；`config/avia.yaml` 显式配置 `g`。`config/pointcloud2.yaml` 的 `/imu/data` 示例显式配置 `mps2`。更换 IMU 时根据实际驱动/数据集单位设置，不通过雷达类型或瞬时加速度大小猜测。

| 输入单位 | 换算到 m/s² 的系数 | 说明 |
|---|---:|---|
| `g` | 9.80665 | `1 g = 9.80665 m/s²`，用于当前 Livox 驱动与 bag |
| `mps2` | 1.0 | 已经是 m/s²，保留数值，不重复乘重力系数 |

换算仅用于监控的诊断和阈值判断，不修改原始 IMU topic 消息。单位参数非法时节点记录 FATAL 并以非零状态退出，避免使用不明单位继续报告健康。模长使用 `std::hypot` 计算。

IMU 诊断保留以下键，RViz 面板显示换算值与原始值：

| 诊断键 | 内容 |
|---|---|
| `linear_acceleration_norm_mps2` | 换算后的加速度模长，显示/判定单位 m/s² |
| `linear_acceleration_norm_raw` | 输入字段原始加速度模长 |
| `imu_acceleration_unit` | 当前配置的原始单位 `g` 或 `mps2` |
| `imu_acceleration_scale` | 输入值到 m/s² 的换算系数 |
| `angular_velocity_norm_rps` | 角速度模长，单位 rad/s |

例如原始模长 `20 g` 对应 `196.133 m/s²`，高于默认 `100 m/s²` 时触发幅值 WARNING；g 和 mps2 两种配置均已实际注入验证。完整 bag 的 287 条诊断也与源消息配对核对通过，详情和截图见[验证记录第 11 节](02_验证记录.md#11-imu-单位修复实测2026-10-10)。

## 2026-10-15：日志时间与封存接口

`EventRecorder(config, LogTimeline)` 接收ROS无关的纳秒时间提供器，事件排队时生成bag回放位置/日期/进度及消息头时间，原单调时间不替换。`bag_log_timeline.h` 在ROS侧只读获取bag起止元数据及/clock，输入适配器用整数秒+纳秒保留source stamp精度。

`finish(reason, context)` 通过独立终结锁保证幂等，在队列锁内停止接收新记录并加入最终RUN_END，等待写线程排空、刷新/同步、关闭；结束后调用event/metrics不再写旧run，也不把主动结束计为丢失。`status()` 新增记录中/封存/已结束字段，面板将主动结束与日志故障分开显示。

自动结束在专用recorded入口显式启用。健康节点除检查源私有播放状态，还确认必需模块已接受同一controller run/instance的STOPPED后封存；原生退出/最终时钟核对仍由C++回放器执行。RuntimeState格式未改，通用入口默认不自动封存。实现范围、字段精度、EOF过渡边界见[20](20_日志时间对齐与回放结束封存.md)。
