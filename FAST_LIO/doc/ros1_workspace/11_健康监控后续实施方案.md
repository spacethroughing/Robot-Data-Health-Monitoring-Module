# 11. 健康监控设计与实施方案

本文说明健康监控模块检查什么、如何告警、怎样处理定位正常停止和重启，以及如何查看记录。当前代码的实现和测试结果见 [12_V2重构实施与测试记录](12_V2重构实施与测试记录.md)。

## 1. 功能范围

模块观察三类数据，并分别给出健康状态：

| 数据 | 主要检查内容 |
| --- | --- |
| 雷达 | 点数、有效点比例、消息频率、时间戳和断流 |
| IMU | 加速度、角速度、单位、字段有效性、频率和时间戳 |
| 定位 | 位姿、时间戳、频率、速度、加速度、协方差和位置跳变 |

每个模块输出 OK、WARNING 或 ERROR。定位是否运行、数据是否可供其他模块使用会另外说明，避免把“进程正常停止”误显示成“定位正常可用”。

## 2. 整体流程

![健康监控简化流程图](images/health_v2_actual_monitoring_flow.png)

监控过程可以概括为：

1. 启动时读取 YAML，检查话题、单位和阈值。
2. 接收雷达、IMU 和定位消息，按各自的数据格式读取内容。
3. 检查数值、时间和数据质量；IMU 按配置统一单位。
4. 将检查结果与 YAML 阈值比较，分别输出模块状态。
5. 在 RViz 面板和 ROS 诊断中显示结果，并写入 JSONL 事件日志和 CSV 指标日志。

## 3. 判断标准

具体阈值在配置文件中按设备设置。表中的项目说明检查内容，不代表通用硬件标准。

### 雷达

- **点数：** 统计收到的总点数和有效点数。
- **有效比例：** 有效点数除以总点数；空扫描单独处理。
- **数据结构：** 检查字段、长度和数据是否能正确读取。
- **时间：** 检查时间戳是否有效、是否重复或倒退，以及两帧间隔。
- **频率和断流：** 统计消息频率，并持续计算距离最后一帧的时间。

### IMU

- **加速度计和陀螺仪：** 检查必需字段是否存在，数据是否为有限数值。
- **单位：** Avia 输入的加速度若以 g 表示，按配置换算为 m/s²；角速度使用 rad/s。
- **幅值和时间：** 检查加速度、角速度、时间戳、频率和断流。
- **协方差、噪声和饱和：** 只有数据含义明确且阈值经过标定时才作判断；未知协方差显示为未知，不当成零噪声。

### 定位

- **输出状态：** 检查定位进程是否应当运行。
- **位姿和时间：** 检查位置、姿态、坐标系和时间戳。
- **运动指标：** 在同一坐标系且样本足够时计算速度、加速度和姿态变化。
- **协方差和跳变：** 检查协方差是否有效，并判断位置或姿态是否异常突变。
- **基线：** 样本不足、重启或坐标系改变时不跨边界计算运动量，暂时显示 N/A。

## 4. 断流计时与等级

断流判断不需要等到下一条消息到达。监控定时器会持续计算“当前时间减去最后一次收到消息的时间”，达到 YAML 中设置的阈值就触发对应状态。

例如，若 IMU 的 WARNING 阈值设为 0.1 秒、ERROR 阈值设为 0.2 秒，那么最后一条消息收到后，经过 0.1 秒触发 WARNING，经过 0.2 秒触发 ERROR。这里使用本机单调时钟；它与消息自身的时间戳是两个不同指标。

- **OK：** 已启用的检查均在正常范围内。
- **WARNING：** 某项指标超过警告阈值，或数据暂时不足以完成判断。
- **ERROR：** 数据结构无效、出现严重数值错误，或指标超过错误阈值。

阈值由设备、采样率和使用环境决定。仓库中的数值是开发与回放起点，部署前应按实际设备标定。

## 5. 正常停止与重新启动

仅凭“暂时没有定位消息”无法分辨正常停止、程序崩溃或数据链路中断。因此，计划停止需要控制器明确发送 STOP，并确认定位进程已经退出。

- **正常停止：** 定位进入 STOPPED，面板显示灰色待机，定位可用性为 false。雷达、IMU 和健康监控仍可继续工作。
- **重新启动：** 控制器发送 RUN。监控为新定位实例建立新数据基线，不使用重启前的时间戳和位置计算速度。
- **启动检查：** 新数据逐步恢复后，按配置确认定位重新就绪；启动失败或超时会单独报告。
- **意外停止：** 没有 STOP 确认时发生进程退出或断流，按异常处理，不当作正常关闭。

运行状态图见 [health_v2_lifecycle_flow.png](images/health_v2_lifecycle_flow.png)。

## 6. C++ 模块分工

项目使用 C++ 类把 ROS 接入、数据判断和显示分开：

- **ROS 节点：** 订阅传感器和定位话题，定时更新监控状态。
- **输入适配器：** 从 ROS 消息中读取字段，并把不同消息整理成监控核心可用的数据。
- **健康核心：** 根据规则和 YAML 阈值判断每个模块的状态。
- **运行控制器：** 发送启动、停止和重启状态，帮助监控区分计划停止与故障。
- **日志记录器：** 保存异常事件、周期指标和运行配置。
- **RViz 面板：** 显示模块状态、检查结果和定位运行情况。

增加一种消息时，通常要增加对应的 C++ 适配代码，并为该数据配置话题、单位和检查阈值。详细类关系见 [13_适配器设计说明](13_适配器设计说明.md)。

## 7. 配置文件

健康监控配置位于 fastlio_health_monitor/config/：

| 文件 | 用途 |
| --- | --- |
| health_v2_avia.yaml | Livox Avia、IMU 和 FAST-LIO 定位的默认配置 |
| health_v2_pointcloud2.yaml | PointCloud2 雷达和标准单位 IMU 的配置示例 |
| health_v2_managed.yaml | 使用运行控制器时的配置 |
| runtime_bag.yaml | 管理式 bag 回放中的进程和命令设置 |
| health_v2_extensions.yaml | 感知诊断和规划数据的接入示例 |

雷达、IMU 和定位的话题及阈值在各配置文件的 modules 部分。断流时间在 stream.receive_age_sec 中设置。日志目录在 logging.directory 中设置。修改参数后需要重新启动监控节点。

planned_config/health_monitor_v2.example.yaml 是设计模板，不是当前节点可直接加载的运行配置。

## 8. 日志记录

日志目录下会按每次运行生成子目录，主要包括：

- **events.0.jsonl：** 状态变化、规则触发、恢复和运行控制事件。
- **metrics.0.csv：** 周期指标，便于查看趋势。
- **配置和版本信息：** 用于确认这次运行采用的阈值和程序版本。

事件带有运行编号、模块编号、实例代号、规则名称和配置摘要，便于把“何时发生、检查了什么、后来如何恢复”串起来。若发生写入错误，日志状态会标记为不完整。

## 9. 当前实现范围

V2 已有雷达、IMU 和定位检查、Avia 单位换算、定位正常停止与重启流程、JSONL/CSV 记录以及 RViz 状态面板。实际验证和已知限制见 [12_V2重构实施与测试记录](12_V2重构实施与测试记录.md)。

设备噪声、零偏、饱和阈值仍需按设备标定；跨设备时钟的绝对传输延迟未启用；PointCloud2、实机运行和定位精度还需要按目标平台继续验证。不要把示例阈值理解为硬件规格。
