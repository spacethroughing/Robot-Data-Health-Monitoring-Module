## 一、项目简介

本项目依托现有 FAST-LIO2 工程，完成 ROS1 工程熟悉、定位健康监控模块和 RViz 可视化检测台。项目面向一个实际使用问题：运行建图定位时，操作者需要同时知道雷达和 IMU 输入是否正常、FAST-LIO 是否持续输出定位，以及 RViz 中看到的地图和点云对应哪些实时数据。

为此，在工作区中增加 C++ 包 `fastlio_health_monitor`。它订阅雷达、IMU 和 Odometry，检查数据质量并发布 OK、WARNING、ERROR 诊断；同时将原始数据、FAST-LIO 输出和健康状态放到一个 RViz 检测台中。launch、YAML 和 RViz 文件负责参数和启动组合，运行时监控与界面功能由 C++ 实现。

## 二、系统如何工作

```text
rosbag 或真实传感器
  ├─ LiDAR ───────────────┬─> FAST-LIO ──> Odometry / 注册点云 / 地图 / Path
  │                       └─> 健康监控：点数、有效比例、时间戳、接收频率
  └─ IMU ─────────────────┬─> FAST-LIO
                          └─> 健康监控：数值有效性、加速度与角速度模长

FAST-LIO Odometry ───────────> 健康监控：位姿、四元数、协方差、速度跳变
健康监控 ── DiagnosticArray ─> RViz 健康面板
传感器及 FAST-LIO 输出 ──────> RViz 三维点云、地图、轨迹和 TF
```

FAST-LIO 负责原有的建图定位；健康监控作为旁路节点观察输入和输出，不替代定位算法。Livox 自定义点云会被转换为 RViz 可直接显示的 PointCloud2，`reflectivity` 映射为 `intensity`。该转换只用于显示，不会执行坐标变换。

## 三、主要实现内容

### 1. 输入数据和定位结果检查

- **LiDAR**：支持 Livox `CustomMsg` 和 `sensor_msgs/PointCloud2` 两种输入。检查消息时间戳、数据结构、总点数、有效点数比例、距离范围和接收频率。Livox 输入还能与驱动给出的 `point_num` 进行一致性检查。
- **IMU**：检查加速度和角速度分量是否为有限值，并根据配置的单位计算模长。针对当前 Livox Avia 数据，输入加速度单位配置为 `g`，监控侧乘以 9.80665 后按 m/s² 显示和判断；PointCloud2 示例配置 `mps2`，不做重复换算。
- **Odometry**：检查位置、四元数、协方差和时间戳，并用相邻位置和消息时间差估计平移速度，识别明显跳变。
- **状态汇总**：监控节点定期结合最新样本结果、消息接收年龄和窗口频率计算分项状态；总体取 LiDAR、IMU、Odometry 中最严重的状态。

输出包括 `/fastlio_health_monitor/diagnostics`（总体与三个分项的 `DiagnosticArray`）和 `/fastlio_health_monitor/status`（0=OK、1=WARNING、2=ERROR 的 `UInt8`）。诊断使用墙钟定时发布，因此 rosbag 仿真时间暂停时，断流监测仍会继续运行。

这些规则用于识别数据异常、断流和明显跳变；状态为 OK 不代表绝对定位精度已得到验证，也不能单独证明不存在地图漂移。

### 2. RViz 可视化检测台

新增 RViz C++ Panel 插件，显示总体状态以及 LiDAR、IMU、Odometry 的分项指标。三维视图同步显示原始雷达点云、FAST-LIO 当前注册点云、累积地图、Odometry、Path 和 TF。

为解决回放时地图闪烁及颜色变化问题，FAST-LIO 增加按需发布地图快照的入口；检测台按约 1 Hz 发布完整地图快照，队列设为 1 并启用 latch。RViz 点云显示使用 intensity 彩虹色，地图强度显示范围固定，点云图层 `Decay Time=0`，减少消息过期导致的空图现象。

### 3. 启动和参数管理

- `health_monitor.launch` 单独启动监控节点并加载 YAML。
- `visualization_testbench.launch` 组合 FAST-LIO、监控节点、Avia 静态 TF 和 RViz，适合实时传感器输入。
- `visualization_bag_testbench.launch` 在检测台上设置仿真时间并启动 rosbag，使用 `--clock` 和 `--wait-for-subscribers`，便于一条命令开展离线回放。
- 阈值、Topic、LiDAR 消息类型和 IMU 单位由 YAML 配置，便于更换输入时调整。

## 五、当前限制与后续计划

目前验证主要覆盖 Livox CustomMsg bag。PointCloud2 分支已经实现并编译，但尚未用对应数据集完成端到端验证；真实 Avia 设备尚未现场联调；没有真值轨迹，因此还没有绝对定位误差评估。健康阈值也需要结合具体传感器、机器人运动范围和现场数据继续标定。

下一步计划：

1. 在真实设备上核对网络、雷达广播码、外参和 IMU 单位，完成实机运行与截图留档。
2. 找到 PointCloud2 数据集完成对应输入分支的端到端验证。
3. 优先处理工程评审中影响状态可信度和长期运行的事项：监控面板诊断超时、短暂异常保留、Odometry 同帧协方差、PointCloud2 尺寸溢出检查、地图快照与后台树重建同步。
4. 在有真值或可对照数据后，再评估定位误差、漂移和阈值误报/漏报。
